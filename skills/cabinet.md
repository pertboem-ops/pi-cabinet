# Cabinet 内阁议事

内阁议事是一种低频重决策模式：在一个父智能体（你）统筹下，4–6 个子智能体
各持异质立场对议题论证、交叉质询、收敛合议，产出一份可追溯的议定书。
阁员之间不直接通信，你是唯一的集成点。

**定位判定**：用户拿不定主意，且选错代价大于议事成本，才值得开阁。成本
列式：直答一问一答 ≈2–5K token；standard ≈14K ≈ 直答 3–7 倍；
advanced/max ≈45–65K ≈ 10 倍以上。拿不准时用评分卡（下文）辅助判断，
并在小题大做时明确告知用户"这题直答更划算"。

## 何时不开阁

- 事实查询、单答案任务、明确的执行型任务。
- 当前处于 **Plan 模式**——插件工具在 Plan 模式下被宿主禁用，内阁议事仅
  Agent 模式可用；遇到时提示用户切换模式。
- 议题可逆且试错成本极低（"先做了再说"比议事便宜）。

## 开阁方式（双通道）

1. **显式调用（主路径）**：用户在输入框输入 `/skill:cabinet` 或直接说
   "开内阁/开阁"，你应当即使用 Skill 工具加载本技能，然后调用
   `plugin_local_cabinet_start` 工具生成编排计划。
2. **自动触发（辅助）**：用户话语命中 description 中的正例时，主动建议
   "这个议题适合开阁议事，要开吗？"——建议而非擅自开阁，因为议事成本显著。

调用工具时传入：topic（必填）、scene（缺省 = general，由你按议题选择
coding/writing/research）、goal（用户说了就传）、tier（**仅当用户显式要求
升档时**才传 advanced/max，否则一律 standard）。

## 档位与预算（双轨：调用轨执法，token 轨参考）

| 档位 | 配置 | 名义 token / 次数 | 次均成本 | 调用轨（执法轨，硬顶） | token 轨（参考轨，软指标） |
|------|------|------------------|---------|------------------------|---------------------------|
| standard（默认） | 4 席 × 1 轮 | 14K / 4 次 | 3.5K/次 | **9 次委派** | 19K |
| advanced（手动） | 5 席 × 2 轮 | 45K / 10 次 | 4.5K/次 | **16 次委派** | 54K |
| max（手动） | 6 席 × 2 轮 | 55K / 12 次 | ≈4.6K/次 | **19 次委派** | 65K |
<!-- tiers-table:end -->

- **记账口径**：只计 Task 子智能体委派次数与子智能体 token；你自身的回合、
  插件工具调用不计。每次重派计入 cost.reassigns（灾备率分母）。**议程
  闭合时在议定书 disclosure 记"调用轨未用 N 次"（N＝cap−calls）**——
  未动用额度不结转不交易、机会成本记 0，但必须写出（第六场 P6-8）。
- **调用轨公式**：cap = 名义 + 一整轮重派 + 1 余量（+1 挂 F2 级联：送达
  核对重取失败 → 缺员重派的那一次）。余量依据 = 1 场实跑观测（2026-10-06
  首场：一次灾备恰好耗尽无余量额度）+ 1 条档案在册的自述记录（v1 原型
  报告，转述级，非独立核验）；reassigns 分母 ≥5 场前数值为**暂定**。
- **token 轨为软指标**：入账不中止，灾备完整性由调用轨承担；数值三档同式
  （标称×1.1 + 次均成本，**四舍五入至千位**：18.9→19、54.0→54、65.1→65）。
  校准口径为"摘录兜底"；R2 全文优先时简报约 ×1.8（第三场 deviation 1.31
  实测），属预期超支。量测以接口口径为准，子智能体内部读取不可观测时
  如实注明。
- **升档即切换预算**：升档须**重调 `plugin_local_cabinet_start`**
  （tier="advanced"、topic 不变）取得含二轮规程的完整计划；已消耗计入
  新档额度；新增席位跳过 R1，直接带全套 R1 材料以二轮身份入席。
- **提前收敛边界（优先级：R1 后必停 > 提前收敛自动跳轮 > 预算切换）**：
  实质分歧恰 1 条 → 跳过质询但**仍须速览后停等用户**；0 条 → 注明
  "首轮即收敛"直接合议。降档自动、升档手动。

## 评分卡（档位建议器，不是门禁）

显式开阁时评分卡只做建议；用户坚持开则开。每项 0–5 分：

| 维度 | 0 分 | 5 分 | 适用场景 |
|------|------|------|---------|
| 选错代价 | 随时可改 | 难回退/返工极贵 | 通用 |
| 信息差 | 信息充分 | 关键信息缺口大 | 通用 |
| 主观分歧度 | 有公认最优解 | 立场强烈对立 | 写作/研究 |
| 传播面/影响面 | 自看自用 | 发布/上线/对外 | 写作/代码 |
| 结论被依赖度 | 一次性参考 | 将作为后续决策依据 | 研究/代码 |

- ≥12 分：建议 standard 档；≥16 分：可向用户建议 advanced（仍需用户确认）。
- <12 分：提示"这题直答 + 一次自检更划算"，用户坚持则按 standard 开阁。

## 议事流程（轮边界 = 对话边界）

完整步骤由 `plugin_local_cabinet_start` 返回的编排计划给出，严格遵循。
核心纪律七条：

1. **R1 后必停**：立场书收齐并核对 → 输出两栏速览（共识面/分歧面对举，v0.3.1 起）→ **停下等用户**。
   共识面逐条列出两席及以上立场重合的命题，每条 = text＋votes（支持席位名单）＋strength＋阶段标注；
   strength 由计数机械派生（分母=到场且显式涉及该命题的席数；未涉及者单列「未表态」，不入分母不计支持；缺席席枚举名单）：全同→[全场一致]；严格过半非全同→[多数 n/m]；无严格过半（2:2、2:1:1 等并列）→[分裂]；
   每条注 [R1 未质询]/[R2 已质询]；[全场一致] 条目旁附伪多样性警示（全场一致≠正确，先查席位异源性）；
   共识面只读、不构成跳轮依据——跳轮仍只看实质分歧条数。
   空面注记：0 条分歧记「首轮即收敛」、共识面记「未采集」，禁止由 0 分歧推强度；共识面为空记「无实质共识」。
   用户可说"进二轮 / 点名 X：问题 / 升档（重调 start）/ 合议 / 散会"。
   用户的回复会在你停下的边界自然送达，不需要也不许抢跑。
2. **续谈一律全新委派**：二轮质询与点名追问都发**全新 Task**，简报内嵌
   该席 R1 立场书**原文**（逐字）——立场连续性靠内嵌原文，不靠会话记忆
   （设计不变量，见下节）。
3. **TaskWait 送达核对与超时语义**：每轮 TaskWait 返回后与派出名单逐一
   核对；缺席者先 TaskList 查状态，completed 而报告缺失的按 delegationId
   重取一次，仍取不到按缺员处理。**TaskWait 超时 ≠ 席位失败**：超时且
   仍在运行 → 续等一次；二次超时或确认失败/中断 → 按缺员重派（计 reassigns）。
4. **转写保真**：质询材料逐字引用原文、只排序不压缩；反驳先引原文并以
   cites（带轮次场次）收尾；任何阁员的立场不得由你改写后传递。
5. **证据标级**：立场书与质询回应中的关键论据必须标注——【核验】亲自读
   文件/跑命令验证、【推断】由材料推理、【转述】引自他席或外部来源。
   跨会话引用必须标注来源会话 id；**审议本项目自身的议题，简报必须附
   完整 runs/ 归档索引，并在议定书声明检索范围**（防"全库检索"语料缺失
   导致的误判）。
   语料纪律两条（20261013-2120 场议定入册）：①2312 P6 勘误对象"三席独立
   互证"系来源不明级（2233 归档五件零命中）——凡引用一律降级表述为
   "2312 据席主张"；②"高性能/顶档"一律改写"其枚举内最高档"——五家
   provider 均无相对强度证据（据席裁决），以档位枚举充强度证据即伪证级
   替换。
6. **混编判定**：按**各席实际解析到的模型**（智能体定义默认模型含专职席
   钉扎 ∪ Task.model 覆盖 ∪ 会话继承）判定单/多源，不是只看委派目录——
   **委派目录为空 ≠ 单源**。红队批判官优先异源。
7. **R2 攻击面**：质询简报**全文优先、摘录兜底**——预算允许时内嵌全部
   对手 R1 立场书原文 + 指定质询点；不可行时至少内嵌指定质询点原文 +
   其余席位速览。行使摘录选择权时在议定书披露。

**简报工程（四件套）**：

1. 需要核验的文件，优先**把关键片段直接内嵌进简报**，或将材料复制进
   工作区后给绝对路径——外部路径受智能体根目录权限约束且随轮次漂移
   （两场实跑独立复现）；
2. 简报引用文件一律绝对路径（相对路径随智能体工作目录漂移）；
3. 文件不可达的席位，简报注明"**以简报材料为据**"，该席不得假装读过文件；
4. 映射席位时按角色卡能力偏好**核对智能体实际工具面**（能读文件/能检索），
   可达性按"智能体 × 路径 × 轮次"三维看待，不假设 R1 可达则 R2 可达。
5. 检索纪律：要求阁员工作区级 Grep 复核时排除 .cabinet 归档目录（限定活文件
   路径或用排除模式）——封存靠纪律不靠机制，历史/封存归档被检索碰破已有
   实跑两起自报（20261013 场）；

**输出格式约束**（随简报直达子智能体）：立场书 ≤600 字（**目标值**；超限
如实标注 over_limit、**不截断归档**——诚实优先于整洁）；结尾给
"最坚持/最没把握"各一点；质询先引原文再驳、被说服明确
"接受此点"；缺 cites 标 `cites_missing: true` 入档并披露。

## 设计不变量

> **不使用 resume**。停等边界（父回合结束）后，未落定的委派链在宿主重建
> 时读作 interrupted，不可续谈（首场实跑观测 + v1 原型报告自述记录）。
> 若误用而断链，按席位失败重派处理（全新委派 + 简报内嵌该席已有材料）。

## 议定书（protocol.json schemaVersion 2）

速览 ≤300 字在前，明细在后。字段：session / tier（含升档路径）/ topic /
brief / seats（每席 seat+agent+model+conclusion，关键论据带证据等级）/ consensus（共识面：text+votes+strength+stage，since 2.2，派生规则见核心纪律 1）/
divergence（每条带状态：未弥合·部分弥合·已解决·新发现）/ decisions
（P1…）/ actions（item+owner+due）/ dissent / disclosure（含补位席注明）/
**beyond_preanswer**（占位列：恒 {count:null,items:[]}，禁止回填——升格须显式
改 verify 断言；2233 P3 绊网，预答测量链不建）/ **degraded**（到场 <3 席时 true）/ cost（calls+tokens_est+cap+cap_hit+
**deviation**：实际/cap 比值+**reassigns**：重派次数）/ archived。

硬性规则：**分歧字段为空且未注明"首轮即收敛"不得合议**（须返回补议）；
缺 cites 的质询回应标注 `cites_missing: true` 入档并披露，不静默接受。
**旧档回放：缺失字段一律记"未采集"/null，禁止默认值回填**（degraded
回填 false 等于虚构事实）。字段清单以 main.js 内 schema 模板为**单一
事实源**，本文档与 README 只引用不复述。

## 灾备路径（只列可发生的活故障，不许静默续跑）

| 故障 | 处置 |
|------|------|
| TaskWait 超时而席位仍在运行 | 续等一次；二次超时按席位失败处理 |
| 席位失败/中断 | 全新委派重派，简报内嵌该席已有材料（预算内常规动作，计 reassigns）；到场 <3 席议定书标 degraded: true |
| TaskWait 报告丢失 | TaskList 查状态 → completed 者按 delegationId 重取一次，仍缺按缺员 |
| 429 / 配额 | 换实际同家族其他模型重试 1 次（计入委派数），仍败按缺员 |
| 全部席位同一家族（按实际解析模型判定） | 开场披露"单源模型分角色推演"后继续 |
| 文件不可达（任意轮次） | 按简报工程四件套处理，声明"以简报材料为据" |
| 归档失败 | 不阻断议定书，末尾标 archived: false 及原因 |

## 归档

由你用自己的文件工具写入项目工作区 `.cabinet/<时间戳>-<slug>/`：
round-N.jsonl（各席原文：席/agent/model/字数/证据等级，R2 含 cites）、
protocol.json（schema v2 全字段）、**events.jsonl（运行日志）**、
index.jsonl（追加行：ts/session/topic/tier/seats/verdict/files/source_doc）。

**events.jsonl 规范 v1.1**：每行一事件
`{seq, t, phase, actor, event, detail?, delegationId?}`——seq 递增；t 为
ISO-8601 时刻，**实时记录优先**；确需事后补录的，t 取可证实的区间下界并
加 `"t_type":"lower-bound"` 标注（不得无标注混用）；**首行允许一条
session_meta 元数据行**（豁免"每行一事件"）；phase 十值 =
`intake | setup | R1 | R2 | steering | upgrade | synthesis | archive |
close | cost`；actor = host|user|runtime|席位名。关键事件至少覆盖：
技能/工具激活、席位映射与三维不重合检查、每次派发、送达核对、故障、
停等与用户裁决、预算切换、归档写入与校验、成本决算。归档使议定书可被
后续会话引用（引用时标会话 id），但归档失败不构成议事失败。

## 角色体系

固定席**红队批判官**完整角色卡（五要素）：

- **职责**：攻击**全体共识中最脆弱的假设**，专找"人人都同意但没人验证过"
  的点；审查对象是议事本身，不是议题正反方。
- **立场锚点**：默认共识是错的，直到经受住最严苛的反驳。
- **必答一问**：如果全场只能保留一条结论，哪一条最先被现实击穿？
- **异质锚点与驳论义务**：只攻击不建设（替代方案留给质询轮）；必须区分
  "致命反驳"与"瑕疵反驳"，不得以数量堆砌伪装强度；必须对多数意见做一次
  "假如它是错的"推演。
- **首选专职席**：cabinet-feng（锋，异源钉扎）；不在场时偏好只读工具面
  智能体（blind-reader > retriever > 任意通用）。

场景角色包（各席位"首选专职席"行见对应角色包技能）：

| 角色包 | 席位（首选专职席） |
|--------|------------------|
| `roles-coding` | 架构官（远 cabinet-yuan）/ 工程官（谋 cabinet-mou）/ 成本官（众 cabinet-zhong） |
| `roles-writing` | 立意官（远 cabinet-yuan）/ 结构官（骨 cabinet-gu）/ 读者代理（众 cabinet-zhong）/ 事实核查官（据 cabinet-ju） |
| `roles-research`（通用默认） | 正方（立 cabinet-li）/ 反方（征召——锋 cabinet-feng 被红队固定席占用，红队走征召时反方可取锋）/ 方法审查官（审 cabinet-shen）/ 信源核查官（据 cabinet-ju） |

**映射两级制**：专职席在场按"首选专职席"行映射；**同一专职席同场不兼任
两席**；缺失或被占用的席位按角色卡能力偏好征召（零配置回退）。
**三维不重合检查**（组阁后必做；判据＝main.js 导出的 checkSeatDimensions
纯函数，smoke 注入负向用例）：气质维（专职席气质不全同）、立场维
（角色卡锚点不全同）、模型维（实际解析模型 ≥2 家族，红队异源）；某维
全重合 → 至少换一席并在 events.jsonl 记录原因。**开场披露必含**：逐席
"设计钉扎 model（ministers/ 定义）vs 实际解析 model"对照，失配记入
protocol.disclosure——只列自报模型清单不算 diff。

**补位规则**：档位席位数超过角色包库存时，按 ① 未在场的专职席（据/众
为通用候补）② 议题邻近的其他角色包选调 ③ 通用席顺序补位；**补位席
优先选用未在场的智能体——复用在场智能体时，该席与被复用席的模型须
异源，或在议定书 disclosure 注明复用**；补位须注明席位及来源包。

用户可在 `skills/roles/` 目录添加自己的角色卡文件并在 manifest 中登记，
即成为新角色包——本技能文案无需改动（发布门对用户新增卡仅警告不拦截）。

## 名单无关性

角色卡绑定的是"能力需求 + 偏好顺序"（首选专职席为第一优先级），不是
具体智能体名。组阁时按当前会话委派目录实际可用的智能体名单映射；
用户新增的智能体自动进入可选池。映射后**核对目标智能体的实际工具面**——
同一会话内不同智能体的文件访问面可能不同，"交叉印证"可能因所指对象
不同而沦为伪印证。
